# TaskFlow — REST API для управления задачами

TaskFlow — REST API на FastAPI для создания, просмотра, обновления и удаления задач. Приложение использует SQLite для постоянного хранения данных и поддерживает фильтрацию, сортировку, пагинацию, сроки выполнения задач и получение статистики.

## Возможности

- Создание задач с названием, описанием, приоритетом и сроком выполнения.
- Просмотр отдельной задачи по ID и получение списка задач.
- Обновление полей задачи, включая изменение или удаление срока выполнения.
- Удаление задач.
- Фильтрация задач по статусу и приоритету.
- Сортировка по ID, названию, приоритету, статусу, сроку выполнения и дате создания.
- Пагинация списка задач с помощью параметров `limit` и `offset`.
- Получение статистики по общему количеству задач и их статусам.
- Проверка работоспособности приложения и получение информации о версии.
- Постоянное хранение задач в базе данных SQLite.
- Логирование запуска приложения и основных операций с задачами.
- Автоматические тесты и непрерывная интеграция через GitHub Actions.

## Установка

Клонируйте репозиторий:

```bash
git clone https://github.com/HoLuG/taskflow-api.git
cd taskflow-api
```

Создайте виртуальное окружение и активируйте его.

**Windows PowerShell:**

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

**Linux / macOS:**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Установите зависимости:

```bash
python -m pip install -r requirements.txt
python -m pip install -r requirements_dev.txt
```

## Конфигурация

Настройки приложения задаются переменными окружения:

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `APP_NAME` | `TaskFlow` | Название приложения |
| `APP_VERSION` | `1.0.0` | Версия приложения |
| `DEFAULT_TASK_PRIORITY` | `medium` | Приоритет задачи, если он не указан |
| `TASKFLOW_DB_PATH` | `taskflow.db` | Путь к файлу базы данных SQLite |

Для настройки через `.env` скопируйте файл-пример:

**Windows PowerShell:**

```powershell
Copy-Item .env.example .env
```

**Linux / macOS:**

```bash
cp .env.example .env
```

При необходимости отредактируйте `.env` и задайте свои значения переменных.

### База данных

TaskFlow использует SQLite. При запуске приложения таблица `tasks` создаётся автоматически, если она ещё не существует.

По умолчанию файл базы данных `taskflow.db` располагается в рабочей директории приложения. Путь можно изменить с помощью переменной `TASKFLOW_DB_PATH`.

Пример настройки:

```dotenv
TASKFLOW_DB_PATH=taskflow.db
```

В отличие от хранения данных в оперативной памяти, SQLite сохраняет задачи между перезапусками приложения. Не удаляйте файл базы данных, если хотите сохранить созданные задачи.

Запустите приложение:

```bash
python -m uvicorn app:app --reload
```

После запуска доступны:

- Приложение: http://127.0.0.1:8000
- Интерактивная документация API: http://127.0.0.1:8000/docs
- Альтернативная документация: http://127.0.0.1:8000/redoc

## API

| Метод | Маршрут | Описание |
|---|---|---|
| `GET` | `/` | Приветственное сообщение |
| `GET` | `/health` | Проверка работоспособности |
| `GET` | `/version` | Название и версия приложения |
| `POST` | `/tasks` | Создание задачи |
| `GET` | `/tasks` | Получение списка задач |
| `GET` | `/tasks/{task_id}` | Получение задачи по ID |
| `PATCH` | `/tasks/{task_id}` | Частичное обновление задачи |
| `DELETE` | `/tasks/{task_id}` | Удаление задачи |
| `GET` | `/stats` | Статистика по задачам |

### Модель задачи

Каждая задача содержит следующие поля:

| Поле | Описание |
|---|---|
| `id` | Уникальный идентификатор |
| `title` | Название задачи, от 1 до 100 символов |
| `description` | Описание задачи, не более 500 символов |
| `priority` | Приоритет: `low`, `medium` или `high` |
| `status` | Статус: `todo`, `in_progress` или `done` |
| `due_date` | Срок выполнения в формате даты и времени либо `null` |
| `created_at` | Дата и время создания задачи |

Новые задачи по умолчанию получают статус `todo`. Если приоритет не указан, используется значение `DEFAULT_TASK_PRIORITY`.

### Создание задачи

Отправьте POST-запрос на `/tasks` с JSON-телом:

```json
{
  "title": "Изучить FastAPI",
  "description": "Реализовать и протестировать REST API",
  "priority": "high",
  "due_date": "2026-11-01T18:00:00+03:00"
}
```

Пример с помощью `curl`:

```bash
curl -X POST http://127.0.0.1:8000/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":"Изучить FastAPI","description":"Реализовать REST API","priority":"high","due_date":"2026-11-01T18:00:00+03:00"}'
```

Поле `due_date` необязательно. Чтобы создать задачу без срока выполнения, его можно не передавать или указать `null`.

### Фильтрация, сортировка и пагинация

Список задач поддерживает следующие параметры:

| Параметр | Возможные значения | По умолчанию |
|---|---|---|
| `status` | `todo`, `in_progress`, `done` | Без фильтра |
| `priority` | `low`, `medium`, `high` | Без фильтра |
| `sort_by` | `id`, `title`, `priority`, `status`, `due_date`, `created_at` | `created_at` |
| `order` | `asc`, `desc` | `desc` |
| `limit` | От 1 до 100 | `20` |
| `offset` | Целое число от 0 | `0` |

Примеры запросов:

```bash
# Получить все задачи
curl "http://127.0.0.1:8000/tasks"

# Отфильтровать задачи по статусу
curl "http://127.0.0.1:8000/tasks?status=todo"

# Найти задачи с высоким приоритетом
curl "http://127.0.0.1:8000/tasks?priority=high"

# Получить первые 10 задач
curl "http://127.0.0.1:8000/tasks?limit=10&offset=0"

# Сортировать по приоритету от высокого к низкому
curl "http://127.0.0.1:8000/tasks?sort_by=priority&order=asc"

# Комбинировать фильтрацию, сортировку и пагинацию
curl "http://127.0.0.1:8000/tasks?status=todo&priority=high&sort_by=created_at&order=desc&limit=10&offset=0"
```

Ответ списка задач содержит массив `items`, общее количество найденных задач `count`, а также применённые параметры `limit` и `offset`.

### Обновление задачи

Для частичного обновления отправьте PATCH-запрос:

```bash
curl -X PATCH http://127.0.0.1:8000/tasks/1 \
  -H "Content-Type: application/json" \
  -d '{"status":"in_progress","priority":"high"}'
```

Чтобы удалить срок выполнения, передайте `null`:

```bash
curl -X PATCH http://127.0.0.1:8000/tasks/1 \
  -H "Content-Type: application/json" \
  -d '{"due_date":null}'
```

Остальные поля нельзя обновлять значением `null`. Пустое тело обновления также не допускается.

### Удаление задачи

```bash
curl -X DELETE http://127.0.0.1:8000/tasks/1
```

### Статистика

Запрос:

```bash
curl http://127.0.0.1:8000/stats
```

Возвращает общее количество задач и количество задач со статусами `todo`, `in_progress` и `done`.

## Тестирование

Запустите автоматические тесты:

```bash
python -m pytest -v
```

Тесты проверяют основные операции с задачами, валидацию входных данных, обработку отсутствующих задач, сроки выполнения, фильтрацию, сортировку, пагинацию и статистику.

Для изоляции тестов используется отдельная временная база данных, поэтому тестовые данные не должны попадать в рабочую базу приложения.

## Непрерывная интеграция

GitHub Actions запускает автоматические тесты при отправке изменений в репозиторий и при создании Pull Request в основную ветку. После успешного выполнения тестов workflow загружает артефакт приложения.

## Логирование

Приложение выводит сообщения о запуске, создании, обновлении и удалении задач. Логи доступны в консоли, в которой запущен Uvicorn.
